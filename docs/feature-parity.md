# Feature parity: Mistral Vibe and the inspiration apps

This fork reimplements Mistral Vibe's desktop app as an open, multi-provider chat built on
[rig](https://rig.rs). This file is the feature-by-feature comparison behind that work. Each row
says what the reference does, what this app does, and where the difference is.

Status: **Done** (matches), **Adapted** (same job, done differently on purpose), **Partial**,
**Missing**, or **N/A** (does not apply to a local, single-user app).

## The inspiration apps

Reviewed in November 2026 feature by feature against the docs of Open WebUI, LibreChat, LobeHub,
Onyx, Osaurus and OpenBot (about 220 features). Every item of the review's shortlist is in the table
below; every feature the review found missing or partial is tracked row by row, with evidence, in
[review-coverage.md](review-coverage.md) (now 211 done, 0 partial, 0 missing, 12 out of scope).
What was deliberately left out, and why:

- **Owner's decision (18 November 2026):** Lumo stays a personal desktop app. Multi-user and
  team features, a Microsoft Teams bot and macOS App Intents (Shortcuts, Siri) are not planned.
  Integrations tested here only against stand-ins (Telegram, Slack, Discord, video generation,
  Qdrant, Tika, ACP, PR status) are left for the owner to try with real accounts.
- **Team and enterprise features** (channels, comments, SSO, SCIM, tenants, admin plane, publishing
  to shared marketplaces): this is a single-user desktop app. Browsing community agents and plugin
  marketplaces is in.
- **Voice cloning and realtime voice models**: provider-specific and outside rig's current
  modalities; image and video generation, editing and voice conversation are covered.

## Built for years of use

| Need | Here |
|---|---|
| A long history stays fast | A conversation index (`chat/index/`) keeps each sidebar row with the file's size and time; listing parses only files that changed. Rebuilt automatically if missing |
| Find anything ever said | Search (Ctrl+K) covers titles and every message, all words must match, with highlighted snippets; `#tag` still filters tags |
| The list stays short | The sidebar shows the newest 30 chats, plus pinned and open ones, then "Show more"; search reaches all |
| It adapts to you | Skills you use most come first in the `/` menu; earlier prompts are a keystroke away (Up, Ctrl+R) |
| Mistakes are recoverable | Deleting moves a conversation to Recently deleted for 30 days (Settings → Profile), with Restore |
| Files are protected | The first change of each day keeps a copy of the conversation as it was; state files are copied daily; 30 days kept |
| Damage is visible | A file that cannot be read is reported in Settings with "Restore the backup"; the damaged file is kept in `quarantine/` |
| Formats can evolve | Each conversation records its format version (`schema`), so migrations know what they read |

## Known gaps

What is not here, and why. Everything else in the Vibe tables is built and was run in the app.

- **Vibe rows that need Mistral's cloud or accounts:** the "Upgrade to Pro" card, skills "Shared
  with me", library roles and organization sharing, `/teleport` to Vibe Code Web, and mobile apps,
  admin rollout and workspaces. Lumo is a single-user desktop app with no account server; the
  nearest local features are sync between your own devices, share links on your network, and
  agent and skill export files. The AFP news feed is Mistral's partnership; the reader works on
  any source instead.
- **Share links reach your network, not the internet:** there is no Lumo server to host pages
  publicly. A page can still be saved as one file and sent.
- **macOS-only and Windows-only paths were not run here:** App Intents (Siri, Shortcuts,
  Spotlight) are not built, as they need Swift on a Mac. Dictation anywhere types with xdotool,
  wtype or ydotool on Linux and pastes on macOS and Windows; computer use on macOS (screencapture,
  cliclick) and on Wayland (grim, ydotool, wtype) is unit-tested, and only Linux/X11 was run.
- **Speech services that need their own keys:** dictation and voice conversation were verified with
  a real speech-to-text model (Whisper tiny.en behind an OpenAI-compatible endpoint). The wake word
  and dictation anywhere were run with the microphone, hotkey and typing real and a stand-in
  transcription server. ElevenLabs needs keys this setup does not have.
- **Coding agents and plugins from GitHub:** the Claude Code CLI ran for real; Codex and Gemini
  CLIs were run as stand-ins with the same command-line shape. ACP agents were tested with a stand-in that speaks the protocol; the Tika and Docling clients were tested against stand-in servers. Video generation was tested against a stand-in for xAI's video service (the account has no credit); this Linux test machine has no H.264 decoder for WebKitGTK (`video/mp4` is reported unsupported), so when a clip cannot play, Lumo converts it once with ffmpeg to Ogg Theora, which the base media plugins decode, and plays that in the chat; verified live, the clip played and looped in the window. Without ffmpeg, a still and "Play in your video player" (the system's player) remain. Downloading a plugin ZIP from
  GitHub was blocked by this environment's network; reading the official marketplace worked.
- **Interface translations:** Portuguese, Spanish, French, German and Arabic were translated by a model
  and have not been reviewed by native speakers.
- **Pull requests on unknown hosts:** a host that is not recognised and prints no link during the
  push gets the branch pushed, and the pull request is opened there by hand.
- **Built-in model speed:** built-in models run on the processor (no GPU or Metal yet). On this 4-core test machine the 0.5B chat model read about 7 prompt tokens and wrote about 8 tokens a second, and Whisper tiny transcribed 11 seconds of speech in 3 seconds; a recent laptop is faster, and larger models are slower.
- **Share links** reach people on the same network while Lumo runs; a link anyone on the internet can open would need a server, which Lumo does not run. "Share as web page" gives a file that can be sent anywhere.
- **Animations:** HyperFrames needs Node.js 22+ and fetches its pinned release from npm on first use; ManimGX must be installed by the user (`uv tool install manimgx`) and its path was not exercised here.
- **Telegram, Slack and Discord** were tested against local stand-ins for their APIs (no tokens here); a Microsoft Teams app is not built (it needs an Azure bot registration and a public endpoint).
- **Local API at start:** the API could fail to start when the app opened (its key read raced the keychain's setup); fixed by setting the keychain up first, verified on three launches in a row.
- **Branding:** the app keeps the Lumo name and logo, as the owner chose.
- **Qdrant** was tested against a stand-in for its REST API (create collection, upsert, filtered delete, filtered search, count); the real Qdrant server was not run here.
